          Security

          No password exists to steal, because none exists at all.

          When you connect a bank or wallet, Atlas never sees or stores the account number, the sort code, or a private key belonging to a wallet you don't control from here. Card connections are switched off for now rather than faked — see below.

          • 01Your identity is a real Ed25519 keypair, generated in this browser. The private key never leaves this device — every request to Atlas is signed locally and verified server-side; nothing is ever transmitted that could let Atlas (or anyone intercepting traffic) reconstruct it.
          • 02A connected source is not itself a cryptographic object — it's a label and an opaque reference tied to your identity in Atlas's database. What's cryptographically real is that connecting one, granting it permission, and spending against it all require a signature only your private key can produce, checked against your public key on every request.
          • 03Every connected source and every permission grant can be revoked independently, for real — a live call to Atlas's server, not a local-only toggle. The server also checks that a request to read or revoke something belongs to the identity that signed the request, not just any registered identity.
          • 04Your private key and recovery shares, if you enable them, are encrypted at rest on this device with AES-256-GCM under a key generated and held here — never transmitted, never sent to Atlas. That's different from Atlas's own server storage: see Anonymity for the honest boundary there.

          There is a real database behind Atlas — a shared ledger needs somewhere to live for bank-funded conversions and balances to work at all, and it deliberately holds as little as that requires: identities (public keys only, no name attached), funding-source labels and opaque references, permission grants, and ledger entries. No password exists anywhere in the protocol to phish, because every sensitive action is a verified signature instead.

          The last 1%

          A few things currently keep this under 100%, stated as plainly as we can manage.

          A real server-side database exists. Bank-funded conversion and a balance you can check from any session both require a shared ledger — that can't live only on your device the way the old fully-local prototype did. What it holds is deliberately narrow (your public key, connected-source labels and opaque references, permission grants, ledger entries) and what it never holds is your private key, a password, or raw account/card data. This is a real trade-off, not a hidden one: a purely local wallet can't fund itself from a bank at all.

          Optional recovery. Off by default. If you enable it, your private key is split into 5 real Shamir secret shares on your device — any 3 reconstruct it, fewer than 3 reveal nothing about it mathematically, not just practically. Choosing this trades a sliver of the purest anonymous state, one with no recovery path at all, for the ability to get back in if you lose access. It can be turned on. It can never be turned off.

          Hosting infrastructure. Running a service on the internet means a request still has to reach a server somewhere, and that layer sees the same ordinary connection data any web host sees (IP address, timing) on top of whatever the request itself carries — which, for Atlas, is never your private key and never a password, only a signature that proves you hold one.

          Card connections are switched off. Not faked with a text field standing in for real capture — genuinely disabled until PCI-compliant tokenization (Stripe) is configured on the backend, so a card number is never something Atlas's own servers see even in transit.

          Local device access. Your private key and recovery shares are encrypted at rest on this device under a key generated and held here, so there's no password to create or remember. That protects your data if it's ever copied or intercepted somewhere else, but not from someone holding this device itself, open and unlocked. No app can fix that. Securing the device is on you.

          We are working toward the smallest server-side footprint a real shared ledger can have: nothing collected beyond what bank-funded conversion structurally requires, and no trade-off left unstated.
